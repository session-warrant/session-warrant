먼저 커널부터 확인합니다.

BPF LSM이 켜져 있어야 나머지가 동작합니다.

  • 커널5.15 이상 · BTF
  • LSM부팅 옵션에 bpf
  • systemdcgroup v2 · logind
  • 개발 기준Ubuntu 24.04 · 커널 6.8
shell
# 받기
git clone https://github.com/session-warrant/session-warrant
cd session-warrant

# 커널 · BTF · lsm · 툴체인 점검
./deploy/bootstrap.sh

# lsm 목록에 bpf 추가 (재부팅 필요)
sudo ./deploy/enable-bpf-lsm.sh

# BPF LSM 동작 확인
make -C bpf && sudo ./bpf/smoke

FAQ

자주 묻는 질문

기록이 외부로 나가나요?

아닙니다. 중앙 서버까지 직접 운영하므로 기록은 내 인프라 안에만 남습니다.

모든 명령을 기록하나요?

실행된 모든 프로세스를 사람에게 귀속시켜 기록합니다. 셸 내장 명령과 키 입력은 남지 않습니다.

에이전트나 중앙이 멈추면요?

발급된 영장은 커널이 계속 집행합니다. 로그인 때 연결에 실패하면 접속은 허용하고 경보를 남깁니다.

막지 못하는 것은요?

다른 데몬에 위임한 실행과 커널 익스플로잇입니다. 알려진 한계는 테스트 케이스로 리포지토리에 있습니다.

기존 게이트웨이와 같이 쓰나요?

네. 게이트웨이는 그대로 두고 각 서버에 에이전트를 설치합니다.

root를 막나요?

root가 하는 일에 사유와 기한을 붙입니다. 커널 익스플로잇 앞에서는 무력합니다.
