# bench/serverload/out/ — 서버 부하 실행 기록

`run.sh` 가 실행마다 `<타임스탬프>/` 를 남긴다.

| 파일 | |
|---|---|
| `env.txt` | 서버 주소 · 프로필 · 노드 수 · 배치 · epoch · k6 버전 · 그때 `audit_event` 행수 |
| `report.txt` | 처리량 · ack 지연 · 읽기 지연 · 판정 |

처리량이 안 늘었다"는 심사 자료이고, 서버 쪽을 고친 뒤(파티셔닝 · 적재 직렬화)
지금 결과와 나란히 놓아야 한다.

## 읽을 때

- **처리량은 `DB 에 들어온 행` 이다.** `보낸 이벤트` 는 상한이다 — 적재가 멱등이라
  epoch 를 새로 안 뽑으면 전건 중복으로 걸러지고도 k6 는 빨랐다고 보고한다.
  `env.txt` 의 `epoch` 가 실행마다 다른지 보면 된다.
- **실행끼리 섞어 비교하지 말 것.** 서버 · DB · k6 가 맥 한 대에서 CPU 를 다툰다.
  노드 수 비교는 같은 묶음 안에서만 한다.
- `env.txt` 의 `db rows` 가 그 실행 시점의 테이블 크기다. 읽기 지연은 이 값에
  좌우되므로, 나중 실행과 비교할 때 먼저 봐야 한다.
