# bench/e2e — 감사 기록 끝에서 끝까지

영장 세션 하나에서 부하를 쏘고, 커널 판정 기록이 **서버 DB 까지 빠짐없이 왔는지** 판정한다.

```
SSH 세션(영장 결속) → 커널 판정 → ringbuf → warrantd → 감사 스트림 → 서버 → audit_event
```

맥에서 돈다. 노드에는 ssh 로, DB 에는 compose 의 PostgreSQL 컨테이너로 붙는다.

## 돌리기

```sh
./audit-load.sh                      # Lima VM sw · Lima 키 · 계정 $USER · 3분
./audit-load.sh --duration 30        # 짧게
./audit-load.sh --key server/.cache/claude_ed25519 --user jonnykim
```

결과는 `out/<타임스탬프>.txt` 에 남는다. 종료 코드는 0 통과 · 1 기록이 모자람 · 2 사전 조건 실패.

## 사전 조건 — 스크립트가 먼저 확인한다

- 서버 · compose(PostgreSQL) · 노드의 warrantd 가 떠 있고 서로 붙어 있다.
- **접속에 쓰는 키 · 계정 · 노드에 결속된 살아 있는 영장**이 있다(`ISSUED`, 회수 안 됨, 부하 + 30초 뒤까지 유효).
  없으면 콘솔에서 신청하고 다른 사람이 승인한다. 스크립트는 키를 노드에 넣지 않는다.
- 영장이 **감사 모드**(OBSERVE · DRYRUN)다. ENFORCE 면 쓰기가 실제로 막혀 부하가 설계대로 돌지 않으므로 거부한다.
- 정책이 `--dir`(기본 `~/sw-e2e`)의 쓰기를 **허용하지 않는다.** 허용된 쓰기는 기록하지 않으므로(§14) 쓰기 판정이 0 이 된다.

## 판정

그 세션의 cgroup id 로 고른 LSM 기록만 센다 — cgroup id 는 재사용되지 않아 다른 세션이 섞이지 않는다.

| 항목 | 회당 | 근거 |
|---|---|---|
| 실행 | ≥ 7 | ls · touch · mv · rm · timeout · bash · sleep. 허용 실행도 기록된다 |
| 쓰기(차단) | ≥ 1 | touch 가 쓰기로 연다 |
| 이름 · 삭제(차단) | ≥ 3 | create · rename · unlink |
| 접속 | ≥ 1 | `--connect`(기본 1.1.1.1:80). 허용 접속도 기록된다 |
| 유실 구간 | 0 | 부하 구간에 그 노드의 `audit_gap` 이 없어야 한다 |

업로드가 끝날 때까지 2초마다 다시 세고, 두 번 연속 같으면 확정한다(최대 60초).
기준은 하한이다 — 로그인 직후 MOTD 실행 등이 더해져 실제 값은 조금 크다.
